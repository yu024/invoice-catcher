## 一、安装与首次打开

### macOS

1. 解压下载的 zip，把 `发票捕手.app` 拖进「应用程序」文件夹。
2. 首次打开会被 Gatekeeper 拦截（提示「无法验证开发者」）：在 Finder 里**右键 App →「打开」→ 再点「打开」**。
3. 如果提示「已损坏，无法打开」，在终端执行一次：

   ```bash
   xattr -cr "/Applications/发票捕手.app"
   ```

   然后再右键打开。

> 分发包使用 ad-hoc 签名、未做 Apple 公证，所以每次系统升级后可能仍需右键打开一次；这不影响功能。

### Windows

1. 双击 `invoice-catcher-setup-<版本>.exe`。
2. SmartScreen 提示「Windows 已保护你的电脑」时，点「更多信息 → 仍要运行」。
3. 安装到当前用户目录，不需要管理员权限。卸载在「设置 → 应用」里进行。

> 首次启动如果弹出防火墙提示，请允许，否则无法连接邮箱服务器。

## 二、准备邮箱：开启服务并获取授权码

### 2.1 先理解三个概念

| 概念 | 说明 |
| --- | --- |
| **IMAP** | 在服务器上读邮件，可以指定文件夹、只同步新邮件、开销小。**推荐**。 |
| **POP3** | 逐封下载收件箱，部分服务商限流，且只能读收件箱。邮箱服务商不支持 IMAP 时才用。 |
| **授权码** | 也叫「客户端专用密码 / 应用专用密码」。**不是网页登录密码**，通常 16 位，只在生成时显示一次，可随时吊销。 |

大部分邮箱在开启「IMAP/POP3 服务」后，必须用授权码登录；直接填登录密码会报「认证失败」。

### 2.2 通用步骤

1. 用浏览器登录邮箱的**网页版**（手机 App 里通常没有这个入口）。
2. 进入「设置 / 账户 / 安全」里的 **POP3 / IMAP / SMTP 服务**。
3. 开启 **IMAP/SMTP**（或 POP3/SMTP），按提示完成短信或扫码验证。
4. 生成「授权码 / 客户端专用密码 / 应用专用密码」，复制下来。
5. 回到发票捕手，粘贴到「密码 / 授权码」输入框，保存。

几个常见坑：

- 只开了 IMAP、没开 SMTP，多数服务商也能收信；但有的要求两者一起开。
- Gmail 的 16 位应用密码带空格，粘贴后可以保留也可以去掉空格。
- 开启两步验证后，登录密码一定不能用于客户端，必须用授权码。
- 改了邮箱密码或吊销过授权码，需要重新生成。

### 2.3 各邮箱具体步骤

#### 网易邮箱（163 / 126 / yeah.net / 188）

1. 浏览器打开 `mail.163.com`（126、yeah.net、188 同理，换成对应域名）。
2. 顶部「设置」→「POP3/SMTP/IMAP」。
3. 开启「IMAP/SMTP服务」，按提示完成手机验证或扫码。
4. 找到「客户端授权密码」，点「新增授权密码」，验证后得到 16 位授权码（**只显示一次**，先复制）。
5. 软件里「邮箱服务商」选「网易 163 / 126 / yeah.net / 188」，服务器地址和端口会自动填好。

> 网易免费版对 IMAP 登录频率有限制，短时间内反复「测试连接」可能被临时限制，等几分钟再试。

#### QQ 邮箱

1. 浏览器打开 `mail.qq.com` 登录。
2. 右上角「设置」→「账号」（部分版本叫「账户」）。
3. 找到「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务」。
4. 开启「IMAP/SMTP服务」，按提示短信验证。
5. 页面会生成一串 16 位授权码，复制。
6. 软件里选「QQ 邮箱」，服务器 `imap.qq.com:993`。

> QQ 邮箱需要先绑定手机号；提示「未实名 / 未绑定」时先按页面指引完成。

#### Gmail

1. 先开启两步验证：登录 Google 账号 →「安全性」→「两步验证」。
2. 打开 <https://myaccount.google.com/apppasswords>，生成「应用专用密码」（16 位）。
3. 确认 IMAP 已启用：Gmail 网页版「设置 → 转发和 POP/IMAP」→ 启用 IMAP。
4. 软件中「密码 / 授权码」填这 16 位应用专用密码。
5. 服务器 `imap.gmail.com:993`，SSL 打开。

> Google 已不再支持「允许不够安全的应用」；没开两步验证就生成不了应用密码。开启「高级保护计划」的账号无法使用应用密码。

#### Outlook / Microsoft 365

微软已对绝大多数账号停用「基本认证」（即用密码或应用密码登录 IMAP/POP），强制走 OAuth2 授权。

- 你的账号如果仍允许：打开 <https://account.microsoft.com/security> →「高级安全选项」→「应用密码」。
- 企业/学校账号需要管理员在 Exchange 管理中心开启 IMAP/POP 并允许基本认证，多数组织已关闭。
- **本工具 v1.0 不支持 OAuth2，Outlook 大概率连不上**，建议改用 QQ、网易或 Gmail 邮箱收发票。

#### iCloud 邮箱

1. 打开 <https://appleid.apple.com> 登录。
2. 「登录与安全」→「App 专用密码」→「生成」，名称随意。
3. 得到 `xxxx-xxxx-xxxx-xxxx` 形式的密码，复制。
4. Apple ID 必须已开启双重认证。
5. 服务器 `imap.mail.me.com:993`，SSL 打开。

#### 阿里企业邮箱

1. 浏览器登录 `qiye.aliyun.com`。
2. 「设置」→「客户端设置」→ 开启 IMAP / POP3。
3. 生成「客户端专用密码」。
4. 服务器 `imap.qiye.aliyun.com:993`。

> 个人 `@aliyun.com` 邮箱不提供 IMAP/POP3，需要企业邮箱账号。

#### 新浪邮箱

1. 浏览器登录 `mail.sina.com.cn`。
2. 「设置」→「客户端 POP/IMAP/SMTP」。
3. 开启 IMAP 服务并生成授权码。
4. 服务器 `imap.sina.com:993`。

#### 其他邮箱

在软件「邮箱服务商」里选「自定义」，手动填写服务商帮助文档里给出的 IMAP 主机和端口（SSL 端口通常是 993，POP3 是 995），再填授权码。

## 三、填写设置并测试连接

右侧「邮箱连接」面板依次填写：

| 字段 | 说明 |
| --- | --- |
| 邮箱账号 | 完整邮箱地址，例如 `name@yeah.net` |
| 密码 / 授权码 | 第 2 步拿到的授权码；已保存过会显示占位提示，留空即保持不变 |
| 收件协议 | 优先 **IMAP**；POP3 仅在服务商不支持 IMAP 时使用 |
| 邮箱服务商 | 选对应品牌，自动带出服务器；其他选「自定义」 |
| 服务器地址 / 端口 | 自动填充，也可手动改 |
| SSL / TLS 加密 | 993 / 995 端口必须打开；用 143 / 110 时才关闭 |
| 收件文件夹 | IMAP 默认 `INBOX`；如果发票被规则归到「发票」「账单」等文件夹，改成对应名称 |

填完点「保存设置」，再点「测试连接」：

- 成功：提示连接成功，并显示该文件夹的邮件总数。
- 失败：底部状态栏会给出原因，对照第 7 节排查。

## 四、开始抓取

### 4.1 两种模式

**A. 本周期增量抓取（默认，最常用）**

不填日期，直接点「开始抓取」：

- 每个周期**第一次**点击时，会把「当天」固定为本周期起始日（界面显示「起始：YYYY-MM-DD」）。
- 之后无论隔几天再抓，都只处理该日期及以后的邮件，不会翻出历史发票。
- 已处理过的邮件靠 UID 位点跳过，不会重复扫描。

**B. 日期区间补抓**

在日期框里填起始 / 结束日期，或点「近7天」，再点「开始抓取」：

- 只扫描这个区间内的邮件，适合补抓上个月漏掉的发票。
- **不会**改动本周期起始日，也**不会**推进增量位点。
- 区间上限：IMAP 最长 366 天，POP3 最长 90 天，超出会自动收敛到上限。

### 4.2 抓取过程中

- 按钮变为「停止抓取」，可随时中断；已保存的发票保留，未处理完的邮件下次会重新扫描。
- 顶部统计实时更新：本次新增、重复跳过、失败、扫描进度。
- 下方「运行控制台」逐条输出日志。

### 4.3 它会抓哪些邮件

1. 主题或正文命中发票关键词（发票、数电票、电子发票、invoice、fapiao），或邮件里带 PDF 附件。
2. 附件是 PDF（按扩展名、MIME 类型、文件头三重判断）。
3. 邮件里没有 PDF 时，尝试打开 4 个发票平台的下载链接：诺诺（nuonuo.com）、金税（jss.com.cn）、百望（baiwang.com）、票纵横（piaozone.com），自动点「下载 PDF」。
4. **自动跳过**：滴滴等平台的「行程单 / 行程报销单 / 行程明细」（RULES.md 第 1 条），避免把行程单当发票。
5. 图片格式（JPG/PNG）的发票暂不处理。

### 4.4 去重规则

- IMAP：`uidValidity + UID` 位点，只扫新邮件；
- 已见邮件 ID 记录，防止重复处理；
- 附件内容 SHA-256，同一张发票即使换了邮件或文件名也会跳过。

## 五、抓取结果与总览表

### 5.1 桌面产物

| 产物 | 位置 | 说明 |
| --- | --- | --- |
| 发票 PDF | 桌面 `发票PDF/` | 文件名格式 `平台_金额元.pdf`，例如 `麦当劳_29.80元.pdf`；重名自动加序号，不覆盖 |
| 发票总览表 | 桌面 `发票总览.xlsx` | 自动更新，可用 Excel / WPS / Numbers 打开 |

保存位置可在界面「数据与周期」里点「发票文件夹」更改。

### 5.2 总览表结构

- **发票明细**：序号、开票日期、平台、类别、金额(元)、发票号码、销方名称、行程、明细、文件名，带筛选与合计行。
- **按平台汇总**：按平台统计张数与金额，带合计。

### 5.3 控制台日志怎么看

| 日志 | 含义 |
| --- | --- |
| `开始抓取 · IMAP · 邮箱` | 已连接服务器，开始本轮 |
| `本周期起始日：YYYY-MM-DD` | 本次增量扫描的日期下界 |
| `增量扫描` | 从上次 UID 位点继续，不重扫旧邮件 |
| `已忽略行程单` | 命中行程单排除规则，跳过不入库 |
| `重复发票已跳过` | 位点 / 邮件 ID / 哈希判重命中 |
| `已保存发票` | 该张发票解析并归档成功 |
| `抓取完成` | 本轮结束，给出新增 / 跳过 / 失败汇总 |

失败条目会显示具体原因（下载超时、解析失败、磁盘写入失败等），失败不会推进 UID 位点，下次会自动重试。

## 六、周期管理与 30 天保留

- **30 天保留**按「抓取时间」计算，不是开票日期。过期记录与对应 PDF 会在三个时机清理：软件启动时、每次抓取结束后、以及运行期间每 6 小时。
- 补抓的历史发票，也从**抓取当天**开始算 30 天，不会因为开票日期早而立刻过期。
- **开启新周期**：清空已抓发票记录与总览表，删除本周期下载的 PDF（只删记录在案的，不会动你手动放进目录的文件），重置去重位点，起始日恢复为「下次点击当天」；**邮箱配置和保存路径保留**，适合按月 / 按项目归档。
- 手动删除桌面 PDF 文件不会删除软件内的记录（总览表里仍有该行）；需要同步清理请用「开启新周期」。

## 七、常见问题排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 提示认证失败 / LOGIN failed | 填了登录密码而不是授权码；服务未开启；授权码被吊销 | 按第 2 节重新生成授权码；确认 IMAP 已开启 |
| 连接超时 / 无法连接服务器 | 主机或端口填错；公司/校园网封了 993/995；需要代理 | 校对参数；换网络（如手机热点）再试 |
| TLS / 证书错误 | SSL 开关与端口不匹配 | 993 / 995 必须开 SSL；143 / 110 关闭 SSL |
| 测试连接成功，但抓不到发票 | 日期区间不对；收件文件夹选错；邮件里没有 PDF；被识别为行程单 | 先清空日期用默认模式试；确认文件夹名；看控制台日志 |
| 一直提示「重复发票已跳过」 | 该发票之前已抓过（同哈希或同邮件） | 正常现象，无需处理 |
| 总览表写入失败 | 文件正被 Excel / WPS 打开占用 | 关闭表格后重试 |
| macOS 提示没有桌面访问权限 | 系统隐私限制 | 「系统设置 → 隐私与安全性 → 文件和文件夹」允许访问桌面 |
| Windows 提示防火墙拦截 | 首次联网 | 允许访问；或手动在防火墙放行 |
| 点了停止但进度条还在动 | 正在收尾当前邮件 | 等几秒；已保存的不会丢 |
| 应用打开白屏 / 报错找不到模块 | 打包产物不完整，或 node_modules 未正确安装 | 重新打包；从源码运行时先 `pnpm install` |
| 发票字段大片空白 | 该地区发票版式不同，文本无法提取 | 属正常降级，PDF 仍会保存并计入汇总 |

如果问题不在表里，把「运行控制台」里的报错原文记下来再排查。

## 八、数据与隐私

### 8.1 数据存在哪

| 内容 | macOS | Windows |
| --- | --- | --- |
| 邮箱配置 | `~/Library/Application Support/发票捕手/config.json` | `%APPDATA%\发票捕手\config.json` |
| 授权码 | 同目录 `secret.bin`（系统安全存储加密，文件权限 600） | 同目录 `secret.bin`（DPAPI 加密） |
| 周期 / 去重记录 | 同目录 `cycle.json` | 同目录 `cycle.json` |
| 发票 PDF 与总览表 | 桌面，可更改 | 桌面，可更改 |

### 8.2 隐私说明

- 所有数据只保存在本机，**不上传任何服务器**。
- 授权码用 Electron `safeStorage` 加密：macOS 走 Keychain，Windows 走 DPAPI；换机器或重装系统后需要重新填写。
- 只有处理「链接型发票」时，才会用隐藏窗口访问诺诺 / 金税 / 百望 / 票纵横这四个域名去下载文件。
- 开源仓库里不包含任何个人邮箱、授权码或发票数据。

### 8.3 彻底清除

1. 软件内「开启新周期」清空发票记录与总览表，并删除本周期下载的 PDF；
2. 删除桌面 `发票PDF` 文件夹和 `发票总览.xlsx`；
3. 删除上面表格里的配置目录（macOS 为 `~/Library/Application Support/发票捕手`，Windows 为 `%APPDATA%\发票捕手`）。

## 九、从源码运行与打包

环境要求：Node.js 18+、pnpm。

```bash
pnpm install
pnpm start            # 启动
pnpm dev              # 启动并打开 DevTools
pnpm run package      # macOS 打包（dist/）
pnpm run package:win  # Windows NSIS 安装包（dist-win/）
```

- macOS 可用 `ARCH=x64 pnpm run package` 打 Intel 版；默认跟随当前机器架构。
- 在 macOS 上交叉构建 Windows 安装包需要 Wine，更推荐在 Windows 或 CI 上原生构建。
- 打包产物未签名：macOS 首次需右键打开，Windows 会提示「未知发布者」。
